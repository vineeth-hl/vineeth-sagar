Overview & Executive Summary

MPI-DG is an inline, multi-stage, zero-trust security proxy that intercepts requests before they reach a foundation model and validates responses before egress. It defends against direct, indirect, multi-turn, and multimodal prompt injection without retraining the underlying LLM or MLLM.

Primary focusZero-trust inline security proxy against direct, indirect, multi-turn, and multimodal prompt injection
Target modelsLLMs & MLLMs — GPT-4o, Gemini, Mistral, LLaVA, SpeechGPT
Core innovationsIFS-R structured-query isolation · SWCSA temporal risk & agent-drift tracking · multimodal frequency-domain / OCR sanitization · Active Overwriting via dynamic suffix optimisation
Theoretical groundingStruQ (USENIX Security '25), Temporal Context Awareness ('25), Agent Drift ('26), SecAlign (Meta / UC Berkeley '25), Mind-Mapping Visual Injection (MDPI '25), Audio Jailbreaks (IEEE '25)
02

Why This Project

  • The generative-AI security paradox — LLMs are trained to follow natural-language instructions flexibly, so they cannot intrinsically distinguish legitimate developer system instructions from untrusted user-supplied data payloads.
  • Traditional boundary defenses fail — keyword blocklists, naive prompt wrapping, and regex all break against semantic paraphrasing, multilingual jailbreaks, adversarial suffix optimisation (GCG), and multi-turn manipulation.
  • The threat horizon is multimodal — malicious commands now hide inside mind-maps, flowcharts, and steganographic noise that trigger during image parsing, and inside token-level adversarial audio perturbations that hijack speech-to-token encoders without alerting a human listener.
  • Enterprise imperatives — safe agent deployment requires preventing unauthorised tool calling, prompt leakage, and data exfiltration without touching foundation-model weights.
03

Zero-Trust Proxy Architecture

The gateway functions as an inline, multi-stage, zero-trust security proxy. Input of any modality is normalised, isolated into a structured envelope, scored for temporal risk, optionally overwritten with a defensive suffix, dispatched to the model, and finally checked for leakage before egress.

04

IFS-R Module — Instruction-Feedback-Structure Sanitization

Theoretical foundation: StruQ: Defending Against Prompt Injection with Structured Queries (USENIX Security 2025).

Mechanism

  • Transforms unstructured prompt payloads into strict schema envelopes using cryptographically random nonce delimiters: <data_slot id="uuid_nonce">…</data_slot>.
  • Employs Structured Instruction Tuning (SIT) syntax to mathematically isolate user data from executable control logic.
  • Neutralises prompt-escape sequences (</system>, \n\nAssistant:) by escaping delimiter collisions at the boundary.
Why dynamic nonces

Static delimiters like """ or ### are trivially guessed and escaped by an adversarial prompt. A fresh per-turn nonce tag makes tag collision mathematically infeasible for the attacker.

05

SWCSA Module — Sliding Window Context Semantic Analysis

Theoretical foundation: Temporal Context Awareness (2025) and Agent Drift: Quantifying Behavioral Degradation (arXiv:2601.04170).

SWCSA maintains an in-memory sliding window of the last K conversation turns per session and halts multi-turn "crescendo" attacks that split malicious intent into individually benign prompts.

Agent Stability Index (ASI)

ASIt = cos ( E⃗system_intent,  E⃗turn_context ) cosine similarity between the system-intent embedding and the current turn's context embedding — a falling ASI signals semantic degradation

Exponentially decaying cumulative risk

Rₜ = α · Rt−1 + (1 − α) · ThreatScore(Turnt) accumulates threat across turns so a slow "salami-slicing" jailbreak still crosses the cutoff
06

Multimodal Preprocessing & Frequency Filter Layer

Theoretical foundation: Mind Mapping Prompt Injection (MDPI Electronics 2025) and Audio Jailbreak Attacks in SpeechGPT (IEEE 2025).

Vision defense
  • Bilateral spatial filtering and normalisation to eliminate high-frequency adversarial perturbations.
  • OCR node parsing to detect and strip covert prompt injections inside diagrams, flowcharts, and mind-maps.
  • Adaptive thresholding, morphological noise removal, and hierarchical node-graph parsing against faint-colour and branch-node evasion.
Acoustic defense
  • Frequency-domain bandpass filtering (Butterworth) to strip ultrasonic / sub-audible adversarial trigger signals.
  • Speech-to-token boundary checks targeting speech-to-token encoders such as SpeechGPT.
07

Active Overwriting & Dynamic Policy Enforcement

Theoretical foundation: SecAlign (Meta / UC Berkeley 2025) and Automatic System Prompt Engineering (2025).

  • K-Means clustering on the prompt representation space classifies attack-intent type.
  • When borderline risk is identified, an optimised defensive suffix is injected dynamically into the system context — forcing the model to adhere to safety alignments without rejecting benign queries.

Attack Taxonomy & Threat Vectors Covered

  1. Direct injection (jailbreaking) — explicit adversarial commands attempting to bypass system safety constraints.
  2. Indirect instruction injection — third-party data carrying stealth instructions that hijack downstream processing.
  3. Multi-turn semantic drift — progressive conversational manipulation designed to bypass single-turn filters.
  4. Visual diagram injection — instructions concealed inside diagram nodes and mind maps.
  5. Acoustic token injection — subtle audio perturbations manipulating speech-to-token embeddings.
  6. Egress leakage / exfiltration — attacks rendering images or markdown links to transmit system secrets externally.

Key Design Decisions & Trade-offs

Inline proxy vs fine-tuning
An inline gateway gives instant zero-downtime deployment, supports proprietary closed-source models, and allows immediate rule updates without GPU retraining cycles.
Cryptographic random delimiters
Per-turn nonce tags instead of static markers — static delimiters are guessed and escaped; dynamic nonces make collision mathematically impossible.
Rolling window vs full graph
Fixed-size sliding window (K = 5) with exponential risk decay keeps Redis memory and vector-calculation latency O(1) while staying sensitive to gradual drift.
Dual-threshold scoring
Low-to-medium risk queries are encapsulated in IFS-R rather than rejected, so technical queries (coding, security research) are not falsely blocked.
