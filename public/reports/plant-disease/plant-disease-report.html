Executive Summary

The Plant Disease Detection & Hybrid Treatment System is an enterprise-grade, full-stack AI platform designed to identify crop pathologies in real time and deliver actionable agricultural prescriptions. By combining a dual-ResNet50 ensemble, synthetic channel-level augmentation, 10-pass test-time augmentation (TTA), and an adaptive hybrid treatment recommendation engine, the system bridges the gap between laboratory deep-learning models and variable real-world farm conditions.

02

Problem Statement & Agricultural Context

2.1 The challenge

Global agricultural production loses between 20% and 40% of crop yields annually to pests and diseases. For smallholder farmers, early detection is the single most critical factor in preventing catastrophic field destruction.

2.2 Limitations of current methods

  • Manual inspection requires certified agronomists — scarce, costly, and unavailable in remote agricultural zones.
  • Standard vision models trained on static datasets such as raw PlantVillage suffer severe distribution shift in the field: direct-sunlight glare and leaf shadowing, lens distortion and colour-balance shifts across phone sensors, and heavy background clutter.
  • No actionable next steps — most tools output a raw disease label with no dosage instructions, organic remedies, chemical treatments, or preventive guidance.
Design goal

Deliver a diagnosis that is resilient to field conditions and pair it with a treatment plan a farmer can act on the same day — online or offline.

Deep Learning & Machine Learning Pipeline

4.1 Model architecture — ResNet-50

The system uses ResNet-50 pre-trained on ImageNet-1K (V2 weights) as the core feature extractor. Identity shortcut connections, y = ℱ(x, {Wᵢ}) + x, mitigate the vanishing-gradient problem across 50 deep convolutional layers. The default 1,000-class head is replaced with a custom linear projection ℝ2048 → ℝ38.

Input (3, 224, 224)
  │
Conv1 (7×7, 64, stride 2) → BatchNorm → ReLU → MaxPool (3×3, stride 2)
  │
Layer 1 : 3 bottleneck residual blocks   [64,  64,  256]
Layer 2 : 4 bottleneck residual blocks   [128, 128, 512]
Layer 3 : 6 bottleneck residual blocks   [256, 256, 1024]
Layer 4 : 3 bottleneck residual blocks   [512, 512, 2048]
  │
Adaptive average pooling (1×1) → flatten (2048-dim vector)
  │
Custom linear classifier (2048 → 38 classes)

4.2 Two-phase transfer-learning strategy

Training is orchestrated in two phases (train.py) to preserve pre-trained feature representations while adapting to leaf-lesion patterns.

Phase 1 — classifier-head warm-up · 3 epochs
  • Backbone weights frozen (requires_grad = False)
  • BatchNorm layers locked in eval mode
  • Train only fc.weight / fc.bias — AdamW, LR 1e-3, weight decay 1e-2
  • Goal: stabilise the randomly initialised classifier without disturbing the extractor
Phase 2 — full backbone fine-tuning · 20 epochs
  • All layers unfrozen (requires_grad = True)
  • BatchNorm active in training mode
  • AdamW with low backbone LR 1e-4
  • CosineAnnealingLR (T_max = 20) · CrossEntropy with label smoothing 0.1

4.3 Optimisation, loss & regularisation

Label-smoothing cross-entropy

ℒLS(y, ŷ) = − ∑i=1K  ( (1 − ε) yᵢ + εK )  log ŷᵢ K = 38 classes · smoothing ε = 0.1 — prevents overconfident predictions on visually ambiguous leaves

Cosine-annealing learning-rate schedule

ηₜ = ηmin + 12 (ηmax − ηmin) ( 1 + cos( tTmax π ) ) Smoothly decays the learning rate to avoid sharp local minima

AdamW optimiser decouples weight decay (10−2) from the gradient update, preventing weight-magnitude explosion during fine-tuning.

4.4 Custom channel-augmentation generator

A dedicated synthetic generator (generate_channel_aug_dataset.py) builds robustness against lighting anomalies, shadow occlusion, and camera colour-filter-array variance.

4.6 Test-time augmentation (TTA) engine

At inference (api/app.py, predict_ensemble_tta.py) the input image is transformed into 5 variants:

  1. T₁ Standard — Resize(256) → CenterCrop(224) → Normalize
  2. T₂ Horizontal flip — T₁ + RandomHorizontalFlip(p=1.0)
  3. T₃ Brightness shift — T₁ + ColorJitter(brightness=(0.8, 1.2))
  4. T₄ Contrast shift — T₁ + ColorJitter(contrast=(0.8, 1.2))
  5. T₅ Combined jitter — T₁ + ColorJitter(b=0.2, c=0.2, s=0.2)

Mathematical fusion

P = 110 ∑m=12 ∑j=15 softmax( ℳₘ( Tⱼ(x) ) ) C* = argmaxc ∈ [1,38] Pc  ·  S* = PC*  — final diagnosis and confidence over P ∈ ℝ³⁸

Backend API & Inference Server — Flask 3.1

6.1 High-performance mixed-precision inference

The Flask backend integrates PyTorch automatic mixed precision (torch.amp.autocast('cuda')). Tensors execute in FP16, cutting VRAM use by roughly 50%, and the 10 TTA forward passes complete in ~120 ms on an RTX-class GPU.

6.2 Hybrid AI treatment advisor

When a disease is classified, the server runs a structured treatment protocol with a hard fallback so a diagnosis is never left without advice.

Offline database structure — 30+ diseases

  • Organic — biological fungicides, copper / sulfur washes, pruning protocols
  • Inorganic — active ingredients: Mancozeb, Metalaxyl, Azoxystrobin, Chlorothalonil
  • Prevention — crop-rotation intervals, drip-irrigation requirements, airflow spacing
  • Application — spray schedule, time-of-day instructions, weather warnings
  • Severity — urgency indicator, e.g. "CRITICAL — can destroy an entire field in 7–10 days"

            ├── 4× treatment action cards (organic, chemical, prevention, severity)
            └── "Analyze Another Plant" reset action

7.2 WebRTC live-camera integration

  • Stream — navigator.mediaDevices.getUserMedia({ video: { facingMode: "environment" } })
  • Frame grab — draw the video frame to an off-screen <canvas>, convert straight to a JPEG blob with canvas.toBlob(...), no base64 overhead
  • Lifecycle — a useEffect cleanup calls track.stop() on every active media track at unmount to release the camera hardware

7.3 UI / UX & styling

  • Tailwind CSS v4 — JIT styling with custom emerald / green gradients
  • Framer Motion — spring physics on hover (scale 1.08, rotateZ −2), staggered card reveals, loading-spinner pulses
  • Dynamic confidence badges — ≥ 70% high 50–69% medium < 50% low

7.4 Reverse-proxy routing

Configured in next.config.mjs — enables zero-CORS config, clean relative fetch('/predict') calls, and a unified security boundary.

Key Architectural & Engineering Decisions

Dual ResNet-50 over one giant model
Two ResNet-50s (standard + channel-aug) instead of a single ViT — lower memory, sub-150 ms latency on mid-tier GPUs, and superior lighting invariance when fused.
5-pass test-time augmentation
Five geometric / colour variants at query time stop a slight camera-angle shift or specular highlight from flipping the prediction.
Decoupled LLM fallback
An internal dictionary of 30+ disease protocols guarantees zero disruption for farmers with intermittent internet or during OpenAI rate limits.
Direct binary-blob streaming
Multipart blobs stream through the Next.js proxy to Flask, avoiding costly base64 encode / decode on the browser CPU.

Installation, Setup & Deployment

Prerequisites

  • OS — Windows 10 / 11, Ubuntu 20.04+, or macOS
  • Python 3.11 or 3.12  ·  Node.js v18+ / v20+ with pnpm
  • Hardware — NVIDIA GPU with CUDA 12.4 recommended (CPU mode supported)

Quick start — one-click PowerShell

.\start.ps1

Manual — backend

cd api
pip install -r requirements.txt
python app.py            # → http://localhost:5000

Manual — frontend

pnpm install
pnpm dev                 # → http://localhost:3000

Optional — dataset augmentation & training

python generate_channel_aug_dataset.py --src-root data/train --out-root data_channel_aug \
       --img-size 224 --target-per-class 150 --copy-originals 0

python train.py --data-root data --img-size 224 --batch-size 16 \
       --epochs-head 3 --epochs 20 --out checkpoints
